# 页面模型与标题算法

这份文档是 agent 的内部规则：如何把一页 Markdown 变成一个 slide 的标题区、面包屑和页面类型。员工只需要读 `markdown-standard.md`。

## 1. 每页的标题栈

每一页独立解析。按出现顺序收集 `#` / `##` / `###`，形成一个标题栈。每个标题先剥掉行首编号，得到显示文字：

```text
# 1 背景                  → (H1, "背景", number="1")
## 1.1 行业现状            → (H2, "行业现状", number="1.1")
### 1.1.1 案例 A           → (H3, "案例 A", number="1.1.1")
```

编号只用于结构校验和目录匹配，不进入 slides。

## 2. 选择主标题

规则一句话：**取“本页只出现一次、且所有祖先也只出现一次”的最深一级标题。**

从 H3 往上找：

1. 页面只有一个 H3，且只有一个 H2、一个 H1
   → 主标题 = H3；面包屑 = `H1 / H2`。
2. 页面有多个 H3，但只有一个 H2、一个 H1
   → 主标题 = H2；面包屑 = `H1`；多个 H3 作为页内小节。
3. 页面有多个 H2（或 H2 的祖先不唯一）
   → 主标题 = H1；无面包屑；多个 H2/H3 作为页内小节。
4. 页面只有一个 H2、没有 H3
   → 主标题 = H2；面包屑 = `H1`。
5. 页面只有一个 H1、没有 H2/H3
   → 正文为空，或只有一段 ≤200 字说明（无列表/表格/代码/图片）= 分区页；
   → 其它情况 = 内容页，主标题 = H1，无面包屑。
6. 页面有多个 H1
   → 取第一个 H1 做主标题，warning。
7. 页面完全没有标题
   → 续页：继承上一页的标题栈，主标题追加“（续）”，warning。

“祖先也唯一”不能省：如果一个 H3 的父 H2 出现两次，不能拿这个 H3 当主标题，否则读者不知道它属于哪个小节。

## 3. 判定表

| 页面里的标题 | 主标题 | 面包屑 | 页内小节 |
|---|---|---|---|
| 一个 H1、一个 H2、一个 H3 | H3 | H1 / H2 | 无 |
| 一个 H1、一个 H2、两个 H3 | H2 | H1 | 两个 H3 |
| 一个 H1、两个 H2、一个 H3 | H1 | 无 | 两个 H2、一个 H3 |
| 一个 H1、一个 H2 | H2 | H1 | 无 |
| 一个 H1 + 一段 ≤200 字说明 | H1（分区页） | 无 | 无 |
| 一个 H1 + 长正文/列表/表格 | H1（内容页） | 无 | 无 |
| 多个 H1 | 第一个 H1 + warning | 无 | 其余作为小节 |
| 无标题 | 上一页标题 + “（续）” | 同上 | 无 |

## 4. 面包屑 B 的 HTML

```html
<section class="slide" data-title="Conditional Access Optimization Agent">
  <div class="slide-content">
    <div class="breadcrumb">
      <span>背景</span><span class="sep">/</span><span>行业现状</span>
    </div>
    <h1 class="slide-title">Conditional Access Optimization Agent：自治边界最清晰的样本</h1>
    <p>正文……</p>
  </div>
</section>
```

- 面包屑：只有主标题的祖先，从 H1 到主标题的上一级。
- 主标题是 H3 → 面包屑 `H1 / H2`。
- 主标题是 H2 → 面包屑 `H1`。
- 主标题是 H1 → 不渲染面包屑。
- 多个 H2/H3 作为页内小节时，用 `<h3 class="sub">` 或 `<h2 class="sub">`，不要重复渲染成页面主标题。

## 5. 目录匹配

目录页由员工手写，agent 只做匹配和渲染：

```markdown
## 目录

- 背景
  - 行业现状
  - 攻击面
- 攻击视角
  - 威胁模型
```

- 一级项 → H1；缩进二级项 → H2。
- 不显示编号、不显示页码。
- 匹配键：剥掉编号、trim、压缩连续空白、忽略大小写后的标题文字。
- 匹配成功：生成可点击项，`data-goto` 用 1-based 页码。
- 匹配不到：保留文字但不加链接，输出 warning。
- 同名标题：匹配第一次出现，输出 warning。
- 员工目录漏项：保留员工目录，输出 warning；不自动追加。
- 整份 Markdown 没有目录页：agent 按文档顺序自动生成 H1/H2 两级目录，放在封面之后。

## 6. 自动目录

没有 `## 目录` 页时：

1. 收集全文 H1/H2。
2. 生成一页目录，标题“目录”。
3. 一级项 = H1，二级项 = H2。
4. 不显示编号、不显示页码。
5. 目录页本身计入总页数，并显示自己的页码。

## 7. 页面类型判定顺序

对每一页依次判断：

1. 首个标题剥编号后是 `目录` / `Contents` / `Table of Contents` → 目录页。
2. 没有标题 → 续页。
3. 只有一个 H1，且正文为空或只有一段 ≤200 字说明、无列表/表格/代码/图片 → 分区页；否则内容页。
4. 其余 → 内容页。

封面不在 Markdown 里；它由 frontmatter 生成，永远排第一页。

## 8. 常见错误

- 把 `---` 当页内分隔线：会被当成分页。
- 只写 H3、不写 H2/H1：结构不完整，warning。
- 编号跳号：仍渲染，但 warning。
- 一页多个 H3 却想用第一个 H3 当标题：违反规则；标题必须停在 H2。
- 目录里写页码或编号：不需要；agent 会忽略编号，页码由系统计算。
