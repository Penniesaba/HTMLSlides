# Markdown Slides 编写标准

这份标准面向写汇报材料的人。按它写，agent 就能稳定生成一份纯白、细线、markdown 风格的 HTML 幻灯片；不按它写，agent 仍会尽量生成，但会给出 warning。

一句话规则：**用 `---` 分页，用 H1/H2/H3 组织标题，用普通 Markdown 写正文，编号手写但不显示。**

---

## 1. 文件与 frontmatter

- 文件必须是 UTF-8 编码的 `.md`。
- 文件最开头可以写一段 YAML frontmatter，用一对 `---` 包住：

```markdown
---
title: Agent Security
subtitle: 智能体安全
kicker: 领域综述汇报 · 2026
author: 张三
date: 2026-10-20
lang: zh-CN
---
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | 是 | 封面主标题；缺失时 agent 用第一个 H1 或文件名代替，并 warning |
| `subtitle` | 否 | 封面副标题 |
| `kicker` | 否 | 封面左上角小标签 |
| `author` | 否 | 封面底部作者 |
| `date` | 否 | 封面底部日期 |
| `lang` | 否 | 默认 `zh-CN`；v1 的界面文字仍以中文为主 |

- 文件最开头那一对 `---` 只当 frontmatter 边界，**不是分页**。
- 封面由 agent 自动生成，不需要在 Markdown 里写封面页。

---

## 2. 分页

- 一行只有 `---`（前后可有空格）表示新的一页。
- 页内如果要有水平分隔线，用 `***`，不要用 `---`。
- 一页就是一个内容片段；标题不会自动分页。
- 页码由 agent 自动计算，员工不写页码。

```markdown
第一页内容

---

第二页内容
```

---

## 3. 标题与编号

### 3.1 层级

| 标记 | 含义 | 例子 |
|---|---|---|
| `#` | H1，部分/大章节 | `# 1 背景` |
| `##` | H2，小节/页面主题 | `## 1.1 行业现状` |
| `###` | H3，具体主题 | `### 1.1.1 案例：Conditional Access` |

规则：

- 不能跳级：H1 → H2 → H3。
- 不能只有 H3 而没有 H1/H2。
- 一页通常从 H2 或 H3 开始；H1 用来开新的部分。
- 一页里可以有多个 H3；这时页面标题会自动停在 H2（见 `page-model.md`）。

### 3.2 编号

员工手写编号，agent 用来校验结构，**不会显示在 slides 里**。

```markdown
# 1 背景
## 1.1 行业现状
### 1.1.1 Conditional Access Optimization Agent：自治边界最清晰的样本
```

- H1：`1`、`2`、`3`……
- H2：`1.1`、`1.2`、`2.1`……
- H3：`1.1.1`、`1.1.2`……
- 编号和标题之间至少一个空格。
- 可以写 `## 2.4. 案例分析`（结尾多一个点也可以）。
- 显示时会剥掉行首编号；标题里后面的数字（`GPT-5`、`2026`）不受影响。

> 编号不连续不会阻断生成，但 agent 会提示你。

## 4. 页面类型

| 类型 | 怎么产生 | 说明 |
|---|---|---|
| 封面 | 自动 | 从 frontmatter 生成；不计入 Markdown 页；显示时无页码，但计入总数 |
| 目录 | 写 `## 目录` | 员工写就按员工的渲染；没写就自动生成 |
| 分区页 | 一页只有 H1（可带一句说明） | 用于“Part 1 / Part 2”这种过渡 |
| 内容页 | 其余页面 | H2/H3 + 正文 |
| 续页 | 一页完全没有标题 | 继承上一页标题并追加“（续）”；不推荐，但允许 |

### 4.1 目录写法

目录只列 H1 和 H2，不列 H3；只写标题文字，不写编号、链接、页码。

```markdown
## 目录

- 背景
  - 行业现状
  - 攻击面
- 攻击视角
  - 威胁模型
  - 案例分析
```

- 一级项对应 H1，缩进二级项对应 H2。
- agent 按“去掉编号后的标题文字”匹配；匹配不到会保留文字并 warning。
- 目录不显示编号，也不显示页码；但目录页本身有右下角页码。
- 如果整份 Markdown 没有 `## 目录`，agent 会在封面之后自动生成一页。

### 4.2 分区页

```markdown
# 2 攻击视角

从攻击者的角度重新看 agent 的组成、入口和风险分类。
```

整页只有一个 H1，加一句 ≤200 字的说明；不要放列表、表格、代码、图片或长段落。否则它会按内容页渲染，而不是分区页。

---

## 5. 正文元素

### 5.1 段落与强调

```markdown
普通段落。**加粗**、*斜体*、`行内代码`。

> 引用块：用于定义、提示、出处。
```

### 5.2 列表

```markdown
- 第一点
- 第二点
  - 一层嵌套
- 第三点
```

- 一页不超过 6 条；超过建议拆页（agent 不会替你拆，只给 warning）。
- 最多一层嵌套。

### 5.3 链接

```markdown
[RSAC 2026 观察](https://example.com/report)
```

- 外部链接会在新窗口打开。
- 链接文字要能独立看懂，不要写“点击这里”。

### 5.4 表格

```markdown
| 风险 | 含义 | 例子 |
|---|---|---|
| 目标劫持 | 改变 agent 的目标 | ... |
| 工具滥用 | 调用不该调用的工具 | ... |
```

- 必须有表头。
- 不超过 6 列；超过建议拆页或用 `<!-- scrollable -->`。
- 单元格里可以用 `<br>` 换行。

### 5.5 代码

````markdown
```python
def hello():
    print("hello")
```
````

- 三反引号围栏，标注语言。
- 不做语法高亮，只保证等宽字体和浅灰底。
- 一页不超过 20 行；超过建议拆页或折叠。

### 5.6 图片

```markdown
![MCP 架构](asset/mcp-architecture.png "图 1：MCP 的三类实体")
```

- `path` 必须是**本地相对路径**，相对当前 Markdown 文件。
- 生成时 agent 会把图片读成 base64，内嵌进最终 HTML；最终 HTML 可以单独发送。
- 不支持远程 URL。远程图或找不到的图会显示占位块，并给 warning。
- 一页默认一张主图；多张图按顺序纵向排列。
- 需要并排时，用页面指令 `<!-- grid: 2 -->` 或 `<!-- grid: 3 -->`，该页只放图片和图注。

### 5.7 水平线

```markdown
***
```

只用于页内分隔；不要用 `---`，那会分页。

### 5.8 折叠块

```html
<details>
<summary>展开看细节</summary>

这里可以继续写 Markdown。

</details>
```

- 只允许 `<details>`、`<summary>`、`<br>`、`<span class="...">`。
- 不允许 `<script>`、`<style>`、`<iframe>`、事件属性或其他原始 HTML。

---

## 6. 页面级指令

写在页面第一行，可以同时出现：

```markdown
<!-- scrollable -->
<!-- grid: 2 -->
```

| 指令 | 作用 |
|---|---|
| `<!-- scrollable -->` | 这一页强制纵向滚动，适用于超长表格/代码 |
| `<!-- grid: 2 -->` | 这一页的图片排成两列；该页只放图片和图注 |
| `<!-- grid: 3 -->` | 同上，三列；该页只放图片和图注 |

默认不滚动：agent 会先自动缩放内容；缩到下限仍放不下才允许滚动。  
**agent 不会替你拆页**——如果一页太密，它会在报告里建议你拆。

---

## 7. 密度建议

- 一页一个中心观点。
- 普通页：不超过 6 条 bullet，或 2 段短文 + 1 个视觉元素。
- 表格：不超过 6 列。
- 代码：不超过 20 行。
- 图片：一页最多 3 张；并排时用 `grid` 指令。
- 超过这些数字不是错误，但会得到 warning，演示效果也可能变差。

## 目录

- 背景
  - 行业现状
  - 攻击面
- 案例分析
  - 案例一
  - 案例二

---

# 1 背景

从标准、攻击和案例三个角度，梳理 agent 安全在 2026 年的变化。

---

## 1.1 行业现状

2026 年被称为 agent 安全的元年。

- 标准组织开始发布 agent 专项风险清单。
- 攻击面从“模型”扩展到“工具链”。
- 安全团队开始把 agent 当作独立资产来管理。

> 这一页只放一个中心观点：agent 安全已经成为一个独立领域。

---

## 1.2 案例：Conditional Access Optimization Agent

### 1.2.1 自治边界最清晰的样本

| 维度 | 观察 |
|---|---|
| 权限 | 只允许读写租户内的条件访问策略 |
| 边界 | 高风险动作必须人工确认 |
| 失败 | 越权请求会被策略层拒绝 |

## 9. 提交前自检

- [ ] 文件开头有 frontmatter，`title` 已写。
- [ ] 分页只用独立 `---`；页内分隔线用 `***`。
- [ ] 标题不跳级；编号连续；编号不显示。
- [ ] 目录只列 H1/H2；没有目录也没关系，agent 会自动补。
- [ ] 图片是本地相对路径；没有远程图。
- [ ] 每页不太密；长表格/代码考虑 `scrollable` 或拆页。
- [ ] 没有 `<script>`、`<style>`、`<iframe>` 或事件属性。
